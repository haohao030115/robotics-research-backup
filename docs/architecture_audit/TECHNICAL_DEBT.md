# Technical debt and architectural risks

Severity: **P0** blocks safe reproducibility or can invalidate a validated runtime; **P1** threatens maintainability or experiment comparability; **P2** is cleanup after contracts are stabilized. Evidence is classified as VERIFIED, INFERRED or UNKNOWN.

| Severity | Finding and evidence | Effect | Proposed treatment | Change risk |
|---|---|---|---|---|
| P0 | Multiple Git repositories and many experiment trees have untracked source; `va_training` Git status lists V4/BCZ/diagnostics as untracked. | A checkpoint may depend on code unavailable from its commit. | Freeze each validated run with source snapshot + dependency lock + commit/hash manifest before any refactor. | Low if additive; high if trying to retroactively merge. |
| P0 | Runtime semantics span Python, C++, DDS, MUSA, MuJoCo and EGL; `native_replay.py` uses PTY/DDS and `v4/rollout.py` uses ZMQ/native CSV. | Small timing or environment changes can alter control behavior. | Keep a frozen runtime lane and introduce typed adapters around it; require golden replay evidence. | High; preserve binary/controller and timing first. |
| P0 | Canonical source policy hashes critical XML, ONNX, C++ and scripts (`source_policy.json`); callers also locate assets through separate path helpers. | Silent asset drift is possible outside guarded entry points. | Centralize read-only manifest resolution after recording current hashes; keep policy gate. | Medium. |
| P1 | `sys.path` insertion and absolute `/workspace/group2` paths occur in runtime/training scripts (`v4/rollout.py:58-68`; ARDY `run_pipeline.py:38-44`). | Imports depend on checkout/mount layout; host/container confusion. | Use installed packages and a generated runtime manifest; preserve container path aliases during migration. | Medium. |
| P1 | Duplicate schema/contract logic across canonical, dl-group2, grasp_pipeline and V4 loaders. | Validation fixes can diverge; repeated conversions are hard to audit. | Define one versioned artifact schema package and have existing validators delegate to it, one boundary at a time. | High if schemas are silently normalized. |
| P1 | Expert producers have incompatible adaptation semantics: Kimodo resampling, ARDY overlap/clearance/calibration, rule generation and generic mirror/IK. | “Shared reference” can hide materially different motion transformations. | Introduce explicit `ReferenceProducer` and `ReferenceAdapter` records with producer-specific metadata; do not merge algorithms. | Medium. |
| P1 | VA model family has V2/V3/V4/V4.1/oracle/BCZ plus baseline/flow, with entry points spread across root scripts and packages. | Checkpoint naming and selection are ambiguous. | Registry keyed by model family, input/output contract, dataset schema and rollout class; retain old entry points as wrappers. | Medium. |
| P1 | Offline evaluation can report good metrics while closed loop fails or task grasp fails; open BCZ report has strict runtime pass but 0.0228 m lift and 0 s hold. | Runtime readiness and task success can be conflated. | Separate gates: schema, offline, scheduler/runtime, physical task. Require all for certification. | Low. |
| P1 | Grasp criterion and hand controller are duplicated in `expert_trajectory.py`, `canonical_va.runtime`, and snapshots. | Contact/lift thresholds can drift. | Make criterion and hand actuator contract a versioned immutable profile consumed by all paths. | High if thresholds change. |
| P2 | Generated outputs, checkpoints, videos and source snapshots coexist beside code. | Searchability and accidental imports suffer. | Move only after artifact registry exists; make generated roots configurable and immutable. | Low to medium. |
| P2 | Legacy synchronous policy/replay code remains importable though archived as non-production text. | New users may select the wrong path. | Mark it diagnostic-only in packaging/CLI and add an explicit production/native mode requirement. | Low. |
| UNKNOWN | Whether every workspace ARDY/Kimodo checkout is still launched externally is not provable because ownership prevents Git inspection and subprocess discovery is incomplete. | Premature deletion could break deployment. | Maintain an allowlisted launch inventory and observe process/shell usage before retirement. | Potentially high. |

Do not classify any module as dead from import absence: shell launchers, subprocess commands, C++ embedding, DDS, dynamic loading and external deployment are present throughout the tree.
